# Ручные проверки 1.0.0

Что не достают тесты и что роняет канал. Журнал — `%ProgramData%\TunnelVPN\state\logs\service.log`
или окно → «Журнал». Основной — туннель с ролью «основной». Перед началом поставить
`TunnelVPN-1.0.0-setup.exe`.

## Включение и ⏻

- [ ] «Выключить», затем «Включить». В журнале «→ туннель поднят за N с», N ≤ 2,3.
- [ ] На включённом VPN нажать ⏻ у туннеля «по списку» — выключается и включается меньше чем за секунду,
      интернет не пропадает.

## Правка конфига основного на живом VPN

- [ ] Открыть активный `.conf` основного, поменять `MTU` (например, 1380 → 1360), сохранить.
- [ ] В журнале есть «→ процесс «…» перезапущен».
- [ ] В журнале нет «→ выход наружу: direct», открытые сайты продолжают грузиться.

## Kill-switch

- [ ] «Настройки → Защита» → включить kill-switch.
- [ ] Сломать основной: в активном `.conf` неверный `Endpoint` (или закрыть его сервер).
- [ ] В журнале «→ выход наружу: block», заголовок окна «Интернет закрыт».
- [ ] Сайты не открываются; туннели «по списку» и локальная сеть работают.
- [ ] Выключить kill-switch — в журнале «→ выход наружу: direct», сайты открываются напрямую.
- [ ] Вернуть правильный `Endpoint`.

## Запасные конфиги основного

- [ ] У основного ≥ 2 `.conf`. Активный сломать (неверный `Endpoint`).
- [ ] В журнале «пробую запасные конфиги», затем «запасной X.conf отвечает — делаю его активным»;
      в окне активным стал X, сайты открываются через туннель.
- [ ] Сломать все `.conf` основного — «запасные конфиги … не отвечают — выход остаётся block»
      (с kill-switch) или «… direct» (без него); новый круг — раз в минуту.
- [ ] Вернуть конфиги.

## IPv6 основного

- [ ] Нужны два конфига основного: с v6-адресом в `[Interface] Address` и без.
- [ ] Переключить конфиг в окне туда и обратно — в журнале нет полного переподключения, открытые сайты
      не рвутся.
- [ ] На конфиге без v6: `curl.exe -6 https://api6.ipify.org` отказывает сразу, не висит.
- [ ] На конфиге без v6 сайты открываются по IPv4, проверка показывает «IPv6 без утечки».
